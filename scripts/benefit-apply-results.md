# 权益调整申请前端核对记录

核对日期：2026-10-26。范围：权益调整申请列表、申请详情、编辑申请、权益调整工作台、选择权益、提交确认。

原型：Axure 项目 2HvdzeaU 的「权益调整申请.html」「权益调整工作台.html」。尺寸、字体和颜色来自浏览器 DOM 与计算样式，未从截图估算。表格、分页、弹框标题和二级标题遵守已确认的系统统一规范。

## 已实现并核对

- 列表筛选：证件类型、号码、客户名称、客户号、机构、起止日期、权益多选、状态、查询和重置。查询/重置为 62×36px；primary 为 #4f6fae，default 保留 Element UI 默认样式。
- 多权益筛选使用“任一权益匹配”。接口仅接受单个 benefitCode，因此逐权益读取全部分页后按申请 ID 去重，再统一分页。查询到多位客户后展示客户选择区，支持全部客户/单客户切换；重置恢复初始状态。
- 申请记录共13列；客户与证件类型补齐。表格/分页12px、单元格上下6px。待审核、已通过仅查看；已驳回可查看、编辑、删除，删除需确认。
- 状态徽标按原型：待审核 #e67e22/#fdf3e7，已通过 #2e7d32/#e8f5e9，已驳回 #c62828/#fdecea。
- 详情1040px：申请内容两列、标签13px #5a6472、结果14px/600 #333a45；逐权益及项目明细；说明、附件、审批信息。审批意见与审批信息为同级标题。审批状态按 status 判断，审批人为空不会误判为未审批。
- 编辑1280px：客户不可修改；选择、移除、展开服务项目配置；日期、保单、OA、原因、说明、附件。按原型直接保存重提，不额外增加二次确认。历史原因缺失时保持待选择，不自动补成新增默认原因。
- 新增进入独立工作台（同一路由 query view=workbench，可刷新/前进/后退）。客户查询框280×38px，候选框560px。输入即发起查询，旧请求不能覆盖新结果。选择保留候选数量/内容，以 #ebf1fa/#2f5496/600 标识选中行，并回显已选客户；确认成功后才关闭候选框。
- 工作台包含客户信息、权益现状7列、权益轨迹10列、权益调整区；中文等级、动作和次数状态；保留数值0，明确无限额度显示“不限”，未知字段显示“—”。
- 选择权益弹框1000px，7列、末尾勾选；按编码/名称/服务商搜索；多选、去重、跨筛选保留勾选。服务项目可配置地区、身份、频次、订单申请、途径、审核；不限次数保留并禁用三个数字输入。
- 新增默认有效期当年年底，禁止过去日期；OA、原因、客户与权益必填；原因编码保留正确映射（权益派发错误REASON05、历史权益修正REASON03）。
- 新增确认框520px，展示客户姓名、权益、有效期、保单、OA和原因；取消不写入，失败保留内容可重试，阻止重复提交。重置只清调整内容，保留当前客户、现状和轨迹。
- 文件选择与jpg/png/pdf、单文件≤5MB校验，调用真实上传/下载接口，失败不假装成功。修复登录态请求拦截器将 multipart 上传改成 JSON 的问题，普通JSON请求行为保持不变。
- 弹框使用固定标题/底部、正文内部滚动；全局滚动条与标题规范继续生效。详情表格不额外产生水平滚动。

## 后端待接入项（本轮不扩展修后端）

1. 申请/修改接口仅保存 benefitCodes 等申请字段，不接受地区、身份、逐项目频次/订单/审核配置；前端已提供原型交互，但这些项目配置不能宣称已持久化。
2. 详情只返回当前规则的部分频次字段，不返回完整项目规则。缺失值显示“—”，未伪造历史申请配置；项目名称/类别使用权益库补充。
3. 附件接口依赖FastDFS，本地不可用。上传成功后使用返回的filePath作为附件标识供下载；权益申请文档将attachment描述为“文件名”，与公共文件服务的路径契约尚需后端确认。未使用本地文件名冒充已上传。
4. 证件字典当前仅返回身份证、护照；前端使用接口值并映射中文展示，未添加后端不识别的原型证件值。
5. 新增、编辑、删除的真实写入尚未在隔离后端联调；本轮写入流程使用API桩验证。完整业务闭环仍需上述后端事项完成后验收。
