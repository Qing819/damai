# INT-015：操作成功、失败提示核对

日期：2026-11-09。

对应腾讯测试文档第 16 行、问题编号 INT-015。文档问题为“成功、失败提示不统一”，要求新增、修改、删除、审批等操作有明确反馈。此次未修改腾讯文档。

## 确认的问题

1. 公共请求封装将部分业务错误拒绝为固定字符串 `error`，丢失后端错误原因及响应上下文。
2. HTTP 200 携带旧格式业务失败状态（如 `status: 500`）时仍会进入页面成功流程，可能显示保存或审批成功。
3. 登录失效分支没有明确提示；请求初始化错误分支没有返回拒绝的 Promise。
4. 积分规则的新增、修改、停用及查询失败分支只打印控制台。
5. 公共层已经提示失败后，操作页还会再显示通用失败提示。

## 本轮修改

| 范围 | 处理 |
| --- | --- |
| 公共请求封装 | 保持成功数据结构与下载数据不变；失败返回带响应上下文的 Error，保留后端原因；补充超时、网络及登录失效提示 |
| 积分计算规则 | 补充新增、修改、停用及查询的失败兜底提示，并返回操作 Promise |
| 客户等级积分配置 | 补充版本/分档加载失败提示；新增、保存、删除、作废失败不重复弹窗 |
| 积分调整申请、积分调整审核 | 新增提交、修改、删除、审核失败不重复弹窗 |
| 权益调整申请、权益调整审批 | 新增/修改提交、删除、通过、驳回失败不重复弹窗 |
| 服务规则配置 | 保存、删除修改记录及导入失败不重复弹窗 |
| 老切新申请 | 新增、导入、批量修改/移除失败不重复弹窗 |
| 积分等级试算 | 批量试算提交失败不重复弹窗 |

页面已有的成功提示保留。对于未被公共层提示的本地异常，页面仍显示兜底失败提示；取消确认对话框维持原有行为。

本轮去重覆盖上述写操作；未将其他所有查询、附件和导出分支一并重构。
