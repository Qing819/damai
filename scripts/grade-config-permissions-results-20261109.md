# 客户等级积分配置：按钮权限核对

核对日期：2026-11-09。环境：本地前端 7001、后端 bxm-points.war 8002、现有 bxm_integral_v2 数据库。

目标测试文档：https://docs.qq.com/sheet/DVGJHR3B2UEZHR0xy?tab=BB08J2

## 可录入的 Bug 条目

标题：客户等级积分配置的按钮权限定义不完整，缺少新增等级、删除等级及版本管理权限。

所属页面：客户等级积分配置（`/personal/plm`）。

接口：`GET /platform/auth/button/getPageButtonMenuInfo?pageType=pointLevelManage`。

复现步骤：

1. 请求上述页面按钮权限接口。
2. 接口成功返回的按钮只有：查询、导出、编辑、等级变更、查看详情。
3. 对照页面的等级分档配置与等级版本管理操作，缺少以下 7 项权限。
4. 查询数据库 `base_element` 中 `url='pointLevelManage' AND type='button'` 的记录，同样仅有上述 5 个按钮，确认缺少按钮定义，不只是当前角色未被授权。

| 缺少的权限名称 | 对应入口或按钮 | 影响 |
| --- | --- | --- |
| 新增等级 | 等级分档配置的“新增等级”及新增保存 | 无法独立授权新增等级分档 |
| 删除等级 | 等级分档列表的“删除” | 无法独立授权删除等级分档 |
| 查看版本管理 | “等级版本管理”页签 | 无法独立授权版本管理入口 |
| 新增版本 | 等级版本管理的“新增版本”及保存 | 无法独立授权新增版本 |
| 修改版本 | 待生效版本的“修改” | 无法独立授权修改入口 |
| 删除版本 | 待生效版本的“删除” | 无法独立授权删除版本 |
| 作废版本 | 生效版本的“作废”及确认作废 | 无法独立授权作废版本 |

预期结果：后端补齐上述页面按钮定义，并按实际角色/机构授权返回。按钮名称需与前端约定一致。

实际结果：后端仍返回客户等级管理的旧按钮集合，无法覆盖当前等级积分配置页面的操作权限。

备注：

- 现有 `编辑`（`btn_pointLevel_edit`，id=1119）用于等级分档编辑；前端也接受明确的 `编辑等级` 名称。该项不计入缺项。
- `等级变更`、`导出`、`查看详情` 不替代新增、删除或版本管理授权。
- `查看版本管理` 只控制页签入口；新增、修改、删除、作废版本分别判断各自权限，同时保留原有版本状态限制。
- 当前本地后端采用免鉴权测试配置。本次结果证明本地按钮定义缺失，不代表已验证生产角色/机构隔离。
- 本轮未新增数据库权限、未修改授权数据，未写入腾讯文档。

## 前端修复与验证

- 仅在客户等级积分配置页面移除默认放行的共享 mixin，直接使用后端按钮列表逐项判断。
- 权限加载前、空列表或请求失败时隐藏操作按钮；取消、关闭等不提交业务变更的控件保持可用。
- 等级编辑与删除、版本修改与删除分别判断权限，避免整列放行。
- 弹窗保存/确认按钮使用对应操作权限；编辑弹窗中的新增行控件使用新增等级权限。
- 使用 `node scripts/check-grade-config.cjs` 验证：真实 Vue 模板编译、单项按钮权限、空/失败返回、完整权限、编辑保存与新增行隔离，以及原有分档、分页、版本日期回归。
- Playwright + 本机 Chrome 实际页面验证通过：真实接口只显示等级编辑；空权限无操作入口；模拟仅版本查看与新增权限时只显示新增；模拟仅版本查看与作废权限时显示作废及确认按钮。模拟只拦截浏览器权限响应，没有写入数据库或提交业务变更。
